## 2. R0 — Claude측(Fable) 독립 설계 초안

### 2.1 요구사항 해석

이 시스템은 검색엔진이 아니라 **하루 1편짜리 편집장**. 목적함수는 recall도 평균 정밀도도 아닌
**precision@1**.

- 결정적 스코어러의 진짜 책무는 최종 랭킹이 아니라 **후보 풀 구성**. 300편 순위의 미세 서열은
  아무도 소비하지 않는다 — 상위 20편이 좋은 집합이기만 하면 된다.
- precision@1을 실제로 책임지는 층은 **LLM 재순위(3층)**.
- 그러나 **precision@1의 상한은 수집 단계가 정한다.** 후보에 NEJM 논문이 없으면 어떤 랭커도
  그것을 뽑을 수 없다. 수집은 주제 recall만이 아니라 **저명저널 recall**도 보장해야 한다.

정리: ① 무관·저품질을 후보에서 제거(결정적) ② 저명저널·전 관심그룹이 풀에 실제로 존재함을
보장(수집) ③ 최종 1편의 침상가치 판단은 LLM 1회 호출에 위임(재순위).
현행은 ③이 한 번도 실행 안 됐고(F1), ①이 오염됐고(F2~F5), ②가 구조적으로 불가능했다(F7).

### 2.2 주범 판정

**"아주 별로"의 주범은 단일 버그가 아니라 F7(천장) × F2(오염) × F1(안전망 부재)의 곱.**

- **F7이 상한을 낮춘다** — 실효 2주 + sepsis 편향 풀에서는 만점 랭커도 "최근 2주 패혈증 논문 중
  최선"밖에 못 뽑는다. 16/25 패혈증, top 저널 0편은 랭커가 아니라 풀의 지문.
- **F2가 그 낮은 상한 안에서조차 순위를 뒤집는다** — 저널 축이 최대 스윙(4.2점)이므로 오염이
  곧바로 top-1을 결정.
- **F1이 마지막 방어선을 제거했다** — 위 둘이 있어도 Opus가 20편을 정독했다면 간호저널 QI 논문이
  1위로 발행되는 일은 대부분 걸렀을 것.

**하나만 꼽으면 F1** — 품질 설계 전체가 "결정적 층의 거친 판단을 LLM이 마무리한다"를 전제하는데,
그 전제가 프로덕션에서 성립한 적이 없다.

**랭킹 아키텍처(3층)는 무죄. 유죄는 구현(F1)·신호 위생(F2~F5)·수집 설계(F7).**
F7만은 버그가 아니라 설계 결함이라 구조 변경 필요. 300편 전량 LLM 스크리닝 전환에는 반대
(429 이력·예산 제약 실재, 결정적 층의 재현성 근거도 유효).

### 2.3 수리 순서

| 순위 | 항목 | 성격 |
|---|---|---|
| P0-1 | F1 env 버그 + 정직한 로깅 | 코드 2줄 · 당일 효과 |
| P0-2 | F2 저널 exact 매칭 전환 | config 재작성 · 당일 효과 |
| P1-1 | F7 이중 스트림 수집 | 구조 변경 · 상한 자체를 올림 |
| P1-2 | F4 설계 축 재배분 + 서술형 리뷰 강등 | 상수 조정 |
| P1-3 | F3 주제 포화 해소 | 공식 1개 교체 |
| P2 | F5·F6 | **수리가 아니라 삭제** |

### 2.4 제안 아키텍처

```
0층 수집   [교체]  단일 쿼리 → 이중 스트림 (A: 최신, B: 저명저널 화이트리스트)
1층 결정적 [축소]  최종랭커 역할 포기 → "게이트 + prior + 풀 빌더"
                   축: 저널(exact) + 주제(탈포화) + 설계(증폭) + 감점 + 게이트
                   삭제: 표본 축, 최신성 축
2층 LLM   [수리]  F1 수정 + 실행 여부를 로그로 증명
3층 PICO  [유지]
```

**0층 — 이중 스트림**
- 스트림 A: 창을 정직하게 30일로 명시. 쿼리에서 `"sepsis"[MeSH]` **제거**
  (`"critical care"[MeSH]`가 이미 덮는 하위 주제인데 독립 항이라 풀의 64% 점령).
  관심그룹 sepsis_shock(weight 1.0)이 있어 랭킹에서 불리해지지 않음.
- 스트림 B(신설): `journals.json`의 top+flagship을 `"저널명"[ta]` OR 체인으로 최근 120일,
  `retmax≈200` 별도 esearch. 처음엔 주제 필터를 붙이지 말 것 — NEJM 중환자 RCT가 EM MeSH를
  안 달고 나오는 경우가 흔하고, 무관 논문은 1층 게이트가 거른다. PMID dedup 후 합집합.
- 날짜 위생: `datetype` `pdat`→`edat`, efetch는 **`ArticleDate` 우선 · PubDate 폴백**.
- 기각안: 주제 그룹별 10분할 쿼리 — recall 균형은 최고나 interests.json과 이중장부화.
  실측 결손은 "저명저널 부재"이므로 B 스트림이 정확한 최소 수리. 그룹 기아가 실측되면 P3로.

**1층 — 저널 축: 부분일치 폐기, exact 매칭**
핵심 논거는 실패 방향 — **부분일치는 fail-open(모르는 저널을 승격), exact는 fail-closed
(모르는 저널을 default 0.8로 중립화)**. 저명도 화이트리스트는 fail-closed가 맞다.
- `includes`는 **low 티어에만** 잔존(`"frontiers in"`, `"bmc "` 같은 패밀리 감점은
  부분일치가 본질적으로 맞는 유일한 자리).
- **ISSN 반대** — 폰에서 `"0090-3493"`을 보고 어느 저널인지 알 수 없어 **모바일 튜닝성과
  실제로 충돌하는 쪽은 ISSN**. exact 저널명이 정확성·가독성 균형점. top 티어에 한해 선택 필드로만.
- 커버리지 공백: "default 티어인데 상위 30 진입" 주간 집계 → 폰에서 리스트에 추가하며 성장.

**1층 — 주제 축: 결정적에 남기되 탈포화**
LLM 전면 이관 반대 — 게이트는 300편 전량 적용 필요(예산 위반), prior 없는 풀은 저널 단독 구성이
되어 "유명하지만 무관심" 논문이 풀을 점령.
```
현행: signal = min(1, titleHits×0.6 + metaHits×0.25)
제안: signal = min(1, 제목히트 체감가중 [0.45, 0.20, 0.10, …] 합 + 0.08×min(metaHits, 3))
```
부수: `cardiac_resus.terms`의 단독 `"cardiac"` 같은 범용어 제거.
검증 관측치: rel01=1.00 비율 ~40% → **10% 미만**.

**1층 — 설계 축: 증폭 + 서술형 리뷰 강등**
`DESIGN_SCALE 0.375 → 0.5`, systematic 아닌 `review` 1.7 → **0.7**.
결과 RCT(2.0) vs 서술형 리뷰(0.35) = **1.65점 차** > flagship↔specialty 격차(1.2)
→ "specialty 저널의 RCT가 flagship의 서술형 리뷰를 이긴다"가 성립.
검증 관측치: 상위 20 풀에서 Review 6편 → 2편 이하, RCT ≥ 4편.

**1층 — 표본·최신성 축: 삭제**
- 표본: 고쳐봐야 0.8점 폭 안에서 노이즈와 경쟁. 결정적 층이 "풀 빌더"로 축소되면
  표본수 판단은 **초록 전문을 읽는 2층이 공짜로 더 잘한다.**
- 최신성: 실효 0.14점짜리 축은 존재 비용이 더 크다. 신선도는 0층 수집 창이 구조적으로 보장,
  동점 분리는 ArticleDate 내림차순 tie-break로 대체. 스트림 B의 90~120일 전 flagship RCT가
  최신성 감점 없이 경쟁하게 되는 것은 **의도된 효과**.

최종: `raw = 저널(-1~4) + 주제(0~4) + 설계(0~2) + 감점 + 게이트(-5)` — 축 5 → 4.

**2층 — F1 수리**
- `Number(process.env.RERANK_POOL || 20) || 20` (빈 문자열·0·NaN 모두 20).
  워크플로 이중 방어: `RERANK_POOL: ${{ vars.RERANK_POOL || '20' }}`.
- **로그 거짓말 제거** — `(LLM reranked)`를 플래그가 아니라 **실행 증거**(`rerankScore` 부착)로
  찍고 `pool=N, llmCalled=true/false`를 남긴다. F1이 4주 은폐된 직접 원인은 버그가 아니라 이 로그.
- 회귀 테스트 2개: `RERANK_POOL=''`일 때 poolSize=20인지, `pool.length > n`일 때 LLM 경로 진입하는지.

### 2.5 기존 설계 원칙에 대한 반론 (쟁점)

- **"모바일 튜닝 = JSON 숫자만"** — 원칙은 지지하나 이것이 **매칭 의미론(부분일치)까지 정당화하는 데
  오용됐다.** 폰에서 고치기 쉬운 것과 폰에서 결과를 예측할 수 있는 것은 다르다.
  `"critical care"` 한 줄이 저널 7종을 승격시키는 config는 튜닝 가능한 게 아니라 지뢰밭.
  exact 리스트 + CI config lint(부분일치 키 금지)가 이 원칙의 올바른 구현.
- **"결정적, 스코어링에 LLM 금지"** — 300편 패스에 한해 유지 찬성. 다만 결정적 층이 표본수·최신성까지
  "품질 추정"을 흉내내려던 것은 과욕. **결정적 = recall과 prior, LLM = precision**을 명시하면
  F5·F6 같은 축은 애초에 존재할 이유가 없다.

### 2.6 누적 38편 리스트 — **폐기 반대**

폐기론의 이득이 사실상 없다. **제외 목록의 38편은 정확히 '이미 발행된' 논문들이고 그중 다수가
나쁜 픽이었다 — 리셋해서 얻는 건 "그 나쁜 픽을 다시 뽑을 권리"뿐.** 반면 놓쳤던 좋은 논문들
(지난 120일의 flagship RCT)은 애초에 선정된 적이 없어 제외 목록에 없고, **스트림 B가 열리는
순간 지금 리스트 그대로도 후보 자격이 있다.**

잃는 것은 명확: 아카이브·대시보드 누적 표·Drive/NotebookLM 적재분과 제외 목록이 서로 다른
우주를 가리키고, 재발행 논문이 텔레그램 중복 발송된다.
→ **제외 목록·아카이브 유지, 대시보드에 "스코어러 v2 적용일" 경계선 1줄만 표기**
(전후 비교가 눈으로 보이는 부수 효과).

### 2.7 품질 측정 — "체감"을 3층위로 대체

1. **리플레이 하네스** `npm run rank-replay` — 후보 풀 스냅샷을 고정 입력으로 구/신 스코어러를
   나란히. 출력은 **폰에서 보는 HTML 1장**(날짜별 구 픽 vs 신 픽, 티어 배지·설계·주제그룹 병기).
   PeterJ 판정 2~3분.
2. **자동 메트릭**(사람 판단 불필요) — ① 간호지·low 티어 픽 수(목표 0) ② 정매칭 top/flagship 픽 비율
   ③ 패혈증 점유율(64% → 30% 미만) ④ 풀 내 RCT+메타 비율 ⑤ rel01 포화율(<10%)
   ⑥ **rerank 실행 증거 로그 존재 여부**(부재 시 CI 실패).
3. **상시 계측** — 데일리 텔레그램에 "차점 2편 + 각 1줄 사유"를 덧붙여 기회비용을 매일 10초에 보고,
   주 1회 👍/👎 집계로 precision@1 시계열. 체감을 버리는 게 아니라 체감을 데이터로 만든다.

### 2.9 리스크

1. **재순위 LLM의 AUP 거부 가능성** — 전량 스크리닝 거부 이력 존재. 완화: 소프트 폴백 이미 있고
   이번 개편으로 폴백 자체 품질이 올라감. 거부율 계수 → 3일 연속 시 알림.
2. **재순위 비결정성** — 완화: 풀 해시 캐시, rerankScore·rationale 전량 로그,
   동점 시 결정적 rawScore tie-break(현행 유지).
3. **exact 리스트 커버리지 공백** — fail-closed는 의도된 방향. 주간 집계로 성장.
   스트림 B가 top 저널 후보 존재를 별도 보장하므로 피해는 중위권에 국한.
4. **스트림 B가 오래된 대작을 반복 상위 노출** — 완화: ArticleDate tie-break,
   필요시 B 창 120→60일(config 숫자 1개).
5. **동시 다발 변경으로 귀인 불능** — 완화: 리플레이에서 축별 on/off 비교를 개편 전 1회.
6. **수집량 증가로 PubMed 429** — efetch +200편/일. 기존 CircuitBreaker·api_key로 흡수 가능.
