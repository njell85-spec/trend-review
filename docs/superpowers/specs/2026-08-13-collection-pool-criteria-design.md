## 0. 이 문서가 뒤집은 것

토론에 실측을 먼저 붙였더니 **양측 전제와 사회자 전제가 모두 반증됐다.**

| 반증된 전제 | 실제 | 확인 방법 |
|---|---|---|
| "최신 구간에 좋은 논문이 적다" | **색인 지연이다.** TIAB·저널 단독은 구간마다 평평(S0 2104 vs S4 2228) | census ⑤ |
| "최신 구간 가중을 올리면 오늘 대작을 잡는다" | **못 잡는다.** MeSH 전용 쿼리가 원리적으로 못 본다 | census ⑤ |
| (A0) "날짜형을 `edat` 으로 하자" | **데일리는 이미 `pdat` 이다** — 개선이 아니라 회귀 제안이었다 | `DataCollectorAgent.js:145` |
| (B0) "저널축 retmax 30 이면 엄격 풀이 자연 포함" | **retmax 는 날짜 절단이지 점수 절단이 아니다**(B1 에서 자진 철회) | 심판 검산 |
| (B1) "S0 저널∧설계의 91%가 MeSH 축 밖 = 지연" | **성숙 구간도 86~89%가 밖이다.** 지연 성분은 약 4%p·구간당 1~3편 — **약 20배 부풀려졌다** | 심판 검산 |
| (양측) "도착률 0.13~0.29/일이라 구조적 적자" | **순환논증.** 지연에 눌린 S0 창에서 잰 값을 공급량 증거로 썼다. 성숙 구간은 **0.63~0.77/일** | 심판 검산 |
| (A1) 전이 38~42일 / (B1) 최소 136일~ | **둘 다 모집단이 틀렸다**(거부하기로 한 설계 필터 풀에서 계산). 대리 모집단 89편+α ÷ 0.23~0.37/일 = **240~387일** | 심판 검산 |

**추가로 이 문서가 확인한 것 — 날짜축이 경로마다 어긋나 있다:**
- 데일리(single stream): `datetype: 'pdat'` (`:145`)
- 이중 스트림 A·B: `_search` 기본값 `'edat'` (`:148` · `:182` · `:196` 이 datetype 미전달)
- 파서의 `paper.pubDate` 는 `History/PubMedPubDate[pubmed]` **우선**이라 사실상 **EDAT**이고
  (`:377-393`), `paper.edat = pubDate` 로 같은 값이 복사된다(`:338`).
→ **쿼리는 pdat, 객체는 edat.** `dateField:"pdat"` 한 줄로는 구간 귀속이 안 되고 **파서 변경이
  필요하다.** 이것은 토론 양측 다 놓쳤고 심판도 부분만 지적했다.

## 1. 합의 설계

### 쿼리 축 (2축 유니온 · 둘 다 주제 조건 포함)
```
축 T : ("emergency service, hospital"[MeSH] OR …6항) OR (interests.json 파생 term [tw])
축 J : (감사된 51종 pubmedTa [Journal]) AND (축 T 주제식)
공통 : NOT ("letter"[pt] OR "editorial"[pt] OR "comment"[pt] OR "news"[pt] OR "published erratum"[pt])
       + 기존 배제 저널 패턴(EXCLUDE_BUILTIN + config patterns)
```
- **PT 는 음성 필터로만.** 양성 필터는 색인 지연에 깨지지만(⑤ S0 44 vs S4 175 = 25%),
  음성 필터는 **지연에 안전한 방향으로 실패한다** — 미색인 신착은 통과하고, PT 가 붙은
  레터는 다음 수집부터 빠진다.
- **주제 조건을 모든 티어에 AND 한다.** 근거: `rel01 == 0` 이면 `topicGatePenalty −5`
  (`MetadataScorer.js:200`) 라 관심어 0매칭 논문은 **사실상 발행 불가**다. 그런 논문을
  저널축으로 긁는 것은 efetch 예산의 순수 낭비다.
- **`[tiab]` 이 아니라 `[tw]`**(title+abstract+MeSH+keyword+substance), 주제어는
  `interests.json` 에서 **자동 파생**. 그러면 **쿼리 매칭면 ⊇ 스코어러 매칭면**이 되어
  "쿼리가 놓쳤는데 스코어러는 잡았을 논문"이 원리적으로 사라진다.

### 구간·할당
- 6구간 × 30일, **`pdat` 귀속**. 구간당 50편(efetch), 총 300 = **현행 예산 불변**.
- 축 예약 **T30 / J20** (잠정 — 근거는 "축 T 가 그외 티어 88~97% 를 보는 유일한 축"뿐).
- **2단 회수**: esearch `retmax=500`/축/구간(PMID만, 사실상 무료) → **esummary 사전순위**
  (docsum 의 `fulljournalname`·`pubtype`·`title` 로 저널 티어·설계·제목히트 복원) →
  **상위 50/구간만 efetch**.
  - 이것이 **날짜 절단을 점수 절단으로 바꾸는 유일한 경로**다. 현행 실효창은
    300/9,264 = **3.2% ≈ 5.8일**이고, 저장소가 이미 같은 결론을 적어 뒀다
    (`MetadataScorer.js:43-44` — *"수집이 최신순 300편이라 실효창이 ~2주"*).
  - 구간을 몇 개로 쪼개도 **회수율 = 할당/풀** 은 안 변한다. Sol 의 "깊이 100"도
    Fable 의 "J20"도 이 비를 못 바꾼다.

### 문턱·가중
- 설계 PT 양성 필터 **없음**. 설계·티어는 전부 스코어러 가점(`boost`).
- 최신 가중 전 구간 **1.0**(코드상 `recencyPart = 0` 이미 그러함).
  동점: `rawScore → pdat_desc → edat_desc → pmid_desc`.

### config 손잡이 (전부 숫자·리스트 — 폰 편집 가능)
```
windowDays 180 · sliceDays 30 · sliceQuota 50 · maxPapers 300
sliceReserve { journal: 20, topic: 30 } · fetchDepthPerAxis 500 · prerank "esummary"|"date"
dateField "pdat" · auditDateField "edat" · topicField "tw"
topicTerms []  (비면 interests.json 자동 파생) · excludeFormats [...] · requireAbstract false
sliceWeights [1,1,1,1,1,1] · tieBreaker ["rawScore","pdat_desc","edat_desc","pmid_desc"]
excludePreviouslyPublished true · journalAliasAuditEnabled true
windowRamp [60,90,120,150,180]     ← ⓒ 완충. 코드가 아니라 숫자로 준다
```

## 2. ⓐⓑⓒ 최종 답

- **ⓐ 설계 필터를 문턱으로 걸지 않는다** — 스코어러 가점으로만.
  성숙 구간 공급이 **0.63~0.77편/일**로 소비 1편/일에 못 미치고, S0 에서 `저널∧설계`가
  성숙치의 **25%(44/175)** 로 눌리므로 **필터는 품질이 아니라 색인 완료 여부를 잰다.**
  전체에 걸면 관찰 43~50%·진단 7~9%·가이드라인이 통째로 빠진다.
- **ⓑ 최신 구간 가중은 1.0 — 추가 가중 없음.**
  공급이 평평하고(TIAB 3,594~4,034 · 저널단독 1,938~2,468, S0 2,104) `recencyPart` 는
  이미 0이다. 최신성은 **180일 컷오프와 동점 분리 두 곳에만** 남긴다(PeterJ 대안 그대로).
- **ⓒ 받아들이되 "1~2주"가 아니라 "수개월"로 계획한다.**
  대리 백로그 **89편(+α)** ÷ 순소진 0.23~0.37/일 = **240~387일**. 현행 실효창이 5.8일~2주라
  180일 재고는 사실상 미개봉이다. 완충은 코드가 아니라 **`windowRamp` 숫자**로 준다.

## 3. 판정 보류 — 이 실측 없이는 못 정한다

| # | 보류 항목 | 필요한 실측(전부 `retmax=0`) | 갈리는 결정 |
|---|---|---|---|
| P1 | 정정판 ④ 구간별 표 | 구간별 `전 티어∧설계` 6개 | 백로그 절대값에 기댄 **모든** 논거 |
| P2 | **축 J 고유 기여** | 구간별 `(51종[Journal]) NOT (MeSH OR tw)` | **축 J 존폐.** ≈0 이면 단일 T축이 이긴다 |
| P3 | 축 J 풀 크기(주제 AND 후) | 구간별 `(51종[Journal]) AND (MeSH OR tw)` | 예약비 T30/J20 확정 |
| P4 | 티어별 발행량 분해 | 구간별 top 6 / flagship 22 / specialty 23 단독 | 티어 비대칭 구조의 유일한 근거 |
| P5 | `[tw]` 주제어 재현율 | `(MeSH 6항)` vs `(tw)` vs 교집합 | 축 T 두께 |
| P6 | `hasabstract` 손익 | 구간별 감소분·가이드라인 손실 | 격식 공백 방어책 채택 여부 |
| P7 | **ⓒ 전이 길이 직접값** | 재생에서 "pdat 60일+ 논문이 top-1 인 날 수" | `windowRamp` 필요 여부 |
| P8 | 13일 빈손 기전 | 재생 로그의 arm별·일자별 `candidateCount` | 아래 ★ 확정 |

**★ "B만 30/30" 은 증거에서 내려야 한다.** 심판이 코드로 짚었다: 단일 arm 후보는
`collectionSources.includes('legacy')` 한정인데(`selectionReplay.js:91-94`) legacy 코퍼스는
`retmax 300 · sort=date` 1회 조회라 **최신 며칠치에 몰려 있다.** `candidatesAsOf` 가
`edat <= day` 로 거르므로 **재생 초반에는 legacy 후보가 구조적으로 0**이다. 즉 그 숫자는
B 의 설계 우월성이 아니라 **B 코퍼스가 창을 덮었다는 사실**을 잰 것에 가깝다.
프로덕션 단일 스트림은 매일 새로 300편을 받으므로 후보 0 은 원리적으로 안 난다.
(완전 확정은 P8 필요 — **부분 확정**.)

## 4. 착수 순서 (되돌리기 쉬운 것 → 어려운 것)

**되돌리기 쉬움 (측정·감사만 · 프로덕션 무접촉)**
1. **census 에 P1~P6 쿼리 추가**(약 30~40회 esearch). **이것 없이는 축 J 존폐도 예약비도 못 정한다. 최우선.**
2. 저널 약어 생존성 감사를 정기 워크플로로 고정(이미 `J Trauma` 1건 적발 — 효과 입증).
3. 파서에 `pdat`/`edat` **병기 필드 추가**. 기존 `pubDate` 의미는 **건드리지 않는다**
   (리포트 표시 계층 보호 = 데일리 코어 무영향).

**중간 (실험 경로 한정 · 스위치로 원복)**
4. 재생 코퍼스를 **180일 전수 기준으로 재구축**한 뒤 E-arm 재생. 한 번에 잰다:
   ①30/30 채움률 ②top-1 의 축 귀속(J 단독 기여) ③`pdat 60일+` 가 top-1 인 날 수(=ⓒ 직접값)
   ④일자별 `candidateCount`(=P8).
5. **esummary 사전순위**를 실험 경로에 먼저 넣고 `prerank` 스위치로 A/B.

**되돌리기 어려움 (마지막 · 게이트 통과 후에만)**
6. 프로덕션 수집기 교체. **컷오버 게이트 = E-arm 30/30 채움 + J축 단독 기여 > 0 + P2 확보.**
   **가장 되돌리기 어려운 것은 발행 이력이다** — 전이가 수개월이면 그 기간 발행분이 중복
   제외 원장에 영구히 남는다. **컷오버 첫날부터 `windowRamp` 를 걸고 시작**해 재고 개방을
   계단화한다.

**범위 밖 (별도 과제)**
7. ⑦ 세 번째 지연 경로 — `_designScore` 에서 PT 미부착 논문이 **1.25점**을 잃는다
   (7.84 → 6.59 실측). 수집단을 고쳐도 남는 점수체계 문제다.
8. **격식 공백** — 미색인 top지 논평(제목 4히트) 8.75 > 완전색인 대표지 RCT 8.2.
   PT 음성 필터는 미색인 비연구물을 못 막는다. `requireAbstract` 가 무코드 방어책 후보(P6).
