# 논문 선정 개선 실험 설계 문서

## 1. 현행 진단 — 세 문제를 코드 수치로

### 문제 1. “180일 수집”이 실제로는 최신 300편 절단이다

현재 수집기는 다음 단일 검색만 실행한다.

- 기간: `SEARCH_DAYS=180`
- 최대 수집량: `MAX_PAPERS=300`
- 정렬: `sort=date`
- 날짜 기준: `datetype=pdat`
- 검색 스트림: 1개

따라서 180일 전체를 재생하는 것이 아니라, 검색 결과 중 최신 300편만 남는다. 과거 실측에서도 확장 MeSH 검색은 30일에 886편이었으므로, 300편은 대략 최근 10일 안팎만 덮을 가능성이 크다. 4~6개월 전 저명저널 RCT·메타분석은 후보 풀에 들어오지 못한다.

한편 [collection.json](/home/user/trend-review/config/collection.json)은 이미 `A=30일/220편`, `B=180일/6슬라이스×16편`, `총 300편`을 선언하지만 [DataCollectorAgent.js](/home/user/trend-review/src/agents/DataCollectorAgent.js:20)가 이 파일을 읽지 않는다. 즉 설정과 실행 코드가 분리돼 있다.

### 문제 2. 주제축에서 검색어 누출 방지 파라미터가 작동하지 않는다

현재 주제 점수는 다음과 같다.

- 제목 히트: `[0.50, 0.25, 0.15, 0.10]`
- MeSH·키워드·초록 히트: `0.08 × min(히트 수, 3)`
- 주제 점수 상한: `rel01 × 4.0`
- 무주제 감점: `-5.0`

탈포화 자체는 구현됐지만, `collection.json`의 `queryMeshExclusions` 6개는 스코어러가 읽지 않는다.

- critical care
- emergency medicine
- intensive care units
- resuscitation
- critical illness
- emergency service, hospital

이 용어들은 모든 후보가 검색 단계에서 이미 갖기 쉬운 신호다. 그런데 [MetadataScorer.js](/home/user/trend-review/src/utils/MetadataScorer.js:337)는 이를 일반 MeSH 히트로 다시 가산한다. 수집 조건이 주제 적합도의 증거로 재사용되는 동어반복이다.

과거 진단 수치도 이를 뒷받침한다.

- 선정 25편 중 검색 MeSH 중복: 22편
- 종전 주제 만점: 25편 중 10편
- 현행 학문 분야 MeSH 검색: 30일 96편
- 진료 세팅 MeSH 확장 검색: 851편
- 합집합: 886편

### 문제 3. 저널 배제가 넓고, 후보가 얕으면 통째로 해제된다

현행 저널 배제는 두 군데에 중복돼 있다.

- 코드 내장 `EXCLUDE_BUILTIN`
- `config/journals.json.exclude.patterns`

간호·영양·재활·교육·보건서비스·수의·치과 등은 감점이 아니라 완전 배제되며, 점수에도 `excludeGate=-10`이 적용된다.

하지만 배제 후 후보가 `topN`보다 적으면 [FilterAnalyzerAgent.js](/home/user/trend-review/src/agents/FilterAnalyzerAgent.js:268)는 배제 전체를 건너뛴다. 즉 동작이 다음 두 극단뿐이다.

- 후보가 충분함: 해당 저널 완전 배제
- 후보가 부족함: 모든 배제 해제

개별 패턴의 과배제율, 배제 저널 중 실제 고가치 논문 비율, 폴백 발동률이 현재 실험 결과에 기록되지 않는다.

## 2. 개선 방향

### 2.1 수집 파라미터

단일 최신순 절단 대신 두 스트림을 사용한다.

| 파라미터 | 현행 | 개선 후보 |
|---|---:|---:|
| 총 후보 상한 | 300 | 300 유지 |
| 스트림 A | 180일 최신 300편 | 30일, `retmax=220` |
| 스트림 B | 없음 | 180일을 30일씩 6분할 |
| B 슬라이스당 | 없음 | 16편 |
| B 문서유형 | 없음 | RCT·메타분석·체계적 문헌고찰 |
| B 주제 필터 | 없음 | 없음 |
| 날짜 기준 | `pdat` | 우선 `edat`, 발행일도 별도 보존 |
| 수집 진실성 | count만 기록 | 실제 최저·최고 날짜 기록 |

B는 저명저널의 고가치 연구를 따라잡는 장치다. 무필터 저명저널 검색은 180일 9,853편으로 너무 넓으므로 설계 필터가 필요하다.

### 2.2 주제축 파라미터

기본 후보는 다음과 같다.

```text
titleWeights = [0.50, 0.25, 0.15, 0.10]
metaHitWeight = 0.08
metaHitCap = 3
queryMeshContribution = 0
topicSpan = 4.0
topicGatePenalty = -5.0
```

핵심 변경은 제목 가중치를 다시 올리는 것이 아니라, 검색에 사용한 MeSH 6개를 주제점수에서 제외하는 것이다. MeSH·초록은 보조 신호로 유지한다.

추가로 반드시 기록할 값:

- `titleHits`
- 제외 전·후 `metaHits`
- `rel01`
- `primaryTopic`
- 각 축의 raw contribution

### 2.3 배제 파라미터

저널 배제를 하나의 on/off 목록으로 취급하지 않고 다음 세 층으로 나눈다.

```text
hardExclude: 명백한 비임상 범주
softExcludePenalty: -1.0 또는 -2.0
allow: 확인된 정상 임상 저널
fallbackMode: 전체 해제 금지
```

권장 초기 구분:

- 하드 배제: 수의·치과·대체의학처럼 범위 밖임이 명확한 항목
- 소프트 감점: 간호·영양·재활·교육·보건서비스
- 허용 목록: 패턴 부분일치로 오탐되는 정상 EM/CCM 저널
- 후보 부족 시: 하드 배제는 유지하고 소프트 감점 논문만 복원

배제 효과는 `excludedCount`, `softRestoredCount`, `falseExclusionRate`로 계측한다.

## 3. A/B/C/D 안 정의

네 안은 한 번에 한 요인만 바꾸는 대조 실험이다. 그래야 어느 변경이 품질 차이를 만들었는지 구분할 수 있다.

| 안 | 현행 대비 차이 | 답하려는 질문 | 주요 위험 | 예상 차이 | 실행 가능성 |
|---|---|---|---|---|---|
| A — 현행 대조군 | 180일·최신 300편, 현행 주제축, 현행 하드 배제 | 현재 품질과 변동성의 기준선은 무엇인가? | 실제 180일 전체로 잘못 해석할 수 있음 | 최신 논문 편중, 오래된 대작 회수 낮음 | ✓ |
| B — 수집 개선 | A 대신 `30일/220 + 180일 6×16` 이중 스트림 | 층화 수집이 오래된 고가치 연구의 recall을 높이는가? | B가 저명저널·고근거 설계에 과도하게 편중될 수 있음 | 후보 연령 범위 확대, RCT·메타 recall 상승 | ✗ |
| C — 주제축 교정 | 수집은 A 유지; 검색 MeSH 6개를 metaHits에서 제외 | 검색어 누출 제거가 주제 만점 포화와 순위 오판을 줄이는가? | 제목 표현이 약한 관련 논문이 하락할 수 있음 | `rel01=1.0` 비율 감소, 제목 근거 논문 상승 | ✗ |
| D — 배제 민감도 | 수집·주제는 A 유지; 하드/소프트/allow 및 단계적 폴백 | 현행 완전 배제가 고가치 논문까지 제거하는가? | 비임상·저가치 논문이 다시 후보에 섞일 수 있음 | 배제 오탐 감소, 폴백의 급격한 품질 변화 감소 | ✗ |

### A — 현행 대조군

- 차이: 없음.
- 질문: 현행 결정적 top-K와 LLM 평가 사이의 recall@K는 얼마인가?
- 위험: 검색 결과가 매일 변하므로 단일 실행을 기준선으로 삼으면 안 된다.
- 예상: 결정적 점수는 안정적이나 오래된 대작 recall이 낮다.
- 실행 가능성: 현재 `selection-experiment.mjs`에서 그대로 실행 가능하다.

### B — 층화 수집안

- 차이: 최신 스트림 A와 저명저널·고근거 설계 스트림 B를 합친다.
- 질문: 동일한 총 300편 예산으로 과거 고가치 연구를 더 많이 회수하는가?
- 위험: 중복 제거, 슬라이스 경계, 저널 청크 결과를 정확히 재현해야 한다.
- 예상: 후보의 실제 날짜 범위와 LLM top-5 recall이 개선된다.
- 실행 가능성: 설정은 존재하지만 수집기가 읽지 않으므로 현재 하네스에서는 불가능하다.

### C — 검색 MeSH 누출 제거안

- 차이: 검색에 사용한 6개 MeSH의 metaHits 기여를 0으로 만든다.
- 질문: 후보 수집량을 바꾸지 않고도 주제축 변별력이 좋아지는가?
- 위험: MeSH 색인이 충분하고 제목이 짧은 관련 논문이 저평가될 수 있다.
- 예상: 주제 만점률과 동점률이 낮아지고, 제목에 임상 문제를 명시한 논문이 상승한다.
- 실행 가능성: 파라미터가 config에만 있고 스코어러가 읽지 않으므로 현재는 불가능하다.

### D — 단계적 배제안

- 차이: 완전 배제 목록을 hard/soft/allow로 분리하고 후보 부족 시 soft만 복원한다.
- 질문: 현행 배제의 정밀도와 품질 순효과는 얼마인가?
- 위험: 전문가 라벨 없이 “오탐”을 자동 판정하면 순환 논리가 생긴다.
- 예상: 간호지 연속 1위 같은 실패는 막으면서도 고가치 다학제 논문의 손실을 줄인다.
- 실행 가능성: 현행 하네스에는 arm별 저널 설정 주입과 배제 전 후보 기록이 없어 불가능하다.

네 안의 1차 비교가 끝난 후에는 B/C/D 중 채택된 요인을 합친 별도 통합 확인 실행이 필요하다. 이 통합 실행을 네 안 중 하나로 미리 넣으면 요인별 효과를 분리할 수 없다.

## 4. 비교 지표와 채택 규칙

### 4.1 평가 데이터

- 같은 실행일·같은 PubMed 기준시각을 사용한다.
- 가능한 경우 최초 수집 PMID와 메타데이터를 스냅샷으로 고정하고 모든 안이 이를 재사용한다.
- 30일 동안 매일 실행하되, 사람이 모든 논문을 평가하기 어렵다면 날짜별 합집합에서 층화 표본을 만든다.
- 임상의 평가는 arm·결정적 순위·저널 점수를 가린 상태에서 실시한다.

### 4.2 핵심 지표

| 영역 | 지표 |
|---|---|
| 임상 품질 | 블라인드 임상의의 최종 1위 선호율, 평균 bedside-value |
| 회수 | LLM/인간 gold top-1의 recall@10·20·50 |
| 주제 | `rel01=1.0` 비율, 무주제율, 단일 주제 최대 점유율 |
| 수집 | 고유 PMID 수, oldest/newest 날짜, B 스트림 기여율 |
| 설계 | RCT·메타·체계적 고찰 비율 |
| 저널 배제 | 배제율, 배제 오탐률, soft 복원률, 폴백 발동률 |
| 안정성 | 날짜별 최종 픽 변동, LLM 반복 간 순위 일치율 |
| 운영 | PubMed 호출 수, LLM 토큰·실패·429, 실행시간 |
| 안전성 | 이미 발행한 PMID 재선정 0건, 상태 파일 변경 0건 |

### 4.3 채택 규칙

공통 안전 게이트:

- 이미 발행한 PMID 재선정: `0`
- 재생 실험이 프로덕션 상태 파일을 변경한 횟수: `0`
- 하네스 실패율: `<5%`
- 배제 오탐률: `<5%`
- 단일 주제 최대 점유율: `<30%`

안별 규칙:

- B 채택: A보다 인간 top-1 recall@20이 최소 `+10%p`이거나, 열세 없이 90일 초과 고가치 연구를 추가 회수해야 한다. 호출량은 A의 `2배` 이내로 제한한다.
- C 채택: 인간/LLM recall@20이 A보다 나빠지지 않으면서 `rel01=1.0` 비율이 최소 `30%` 상대 감소해야 한다.
- D 채택: A 대비 고가치 오배제를 최소 `50%` 줄이고, 최종 후보의 저가치 저널 비율 증가는 `+5%p` 이하여야 한다.
- 통계적으로 애매하면 현행 A를 유지한다. 단, A의 구조적 결함을 “차이가 유의하지 않다”는 이유만으로 해결된 것으로 간주하지 않는다.
- 여러 변경이 통과하면 통합안을 같은 스냅샷에서 다시 재생하고, A 대비 비열등성까지 확인한 후 프로덕션에 반영한다.

## 5. 실험의 한계

### MeSH 색인 지연

최신 논문은 MeSH가 아직 부여되지 않았을 수 있다. 따라서 MeSH 기반 주제 점수와 쿼리 비교는 최신 논문을 체계적으로 저평가할 수 있다.

대응:

- MeSH 존재율을 날짜 구간별로 보고한다.
- 제목·초록 기반 결과와 MeSH 포함 결과를 분리한다.
- `edat`와 실제 발행일을 함께 저장한다.
- 최신 7일 결과를 MeSH 변경의 최종 판정 근거로 단독 사용하지 않는다.

### 30일 샘플 크기

시스템은 하루 1편을 고르므로 30일 최종 픽은 최대 30건이다. 비율 1건이 3.3%p이므로 작은 차이는 우연과 주제 유행에 크게 흔들린다. 패혈증 대형 연구가 집중된 달과 그렇지 않은 달의 결과도 다르다.

대응:

- 30일은 파일럿으로 규정한다.
- 최종 채택은 가능하면 60~90일 리플레이 또는 복수 월 스냅샷으로 확인한다.
- 모든 비율에 `n`을 병기한다.
- 평균 점수보다 날짜별 paired win/loss를 우선한다.

### LLM 변동성

같은 후보라도 모델 버전, 프롬프트, 샘플링, 제공 순서에 따라 순위가 달라질 수 있다. LLM을 gold standard로 간주할 수 없다.

대응:

- 모델·프롬프트·응답·후보 순서를 기록한다.
- 후보 순서를 섞어 최소 3회 반복하는 안정성 표본을 둔다.
- LLM 결과와 블라인드 임상의 판정을 분리 보고한다.
- 재순위 응답이 후보 PMID 전체를 포함하지 않으면 해당 실행을 무효 처리한다.
- 모델 변경이 발생하면 전후 결과를 같은 실험으로 합치지 않는다.

그 밖의 한계:

- 저널과 연구 설계는 임상가치를 대리하는 신호일 뿐이다.
- PubMed 비수록 가이드라인·학회 웹 문서는 평가 대상이 아니다.
- A/B/C/D가 동일한 고정 메타데이터를 쓰지 않으면 PubMed 갱신이 arm 효과로 오인될 수 있다.
- B/C/D의 개별 효과가 통합안에서도 단순 가산된다는 보장은 없다.
- 과거에 이미 선택된 논문만 평가하면 현행 시스템의 선택 편향이 재현된다.

## 6. 실행 가능성 점검

현재 재생 하네스는 다음만 외부에서 바꿀 수 있다.

- `EXP_MAX`
- `EXP_CHUNK`
- `EXP_LLM`
- `EXP_MODE`
- `RERANK_POOL`

수집 쿼리·스트림·주제 가중치·검색 MeSH 배제·저널 배제 정책은 arm 파라미터로 받을 수 없다.

| 안 | 변경 사항 | 현재 하네스 실행 | 판정 근거 |
|---|---|:---:|---|
| A | 현행 단일 수집 | ✓ | `DataCollectorAgent.run()` 직접 사용 |
| A | 현행 주제축 | ✓ | `MetadataScorer` 직접 사용 |
| A | 현행 저널 배제 | ✓ | `_selectTopPapers()` 직접 사용 |
| A | recall@K·LLM 평가 | ✓ | 기존 기본 모드 제공 |
| B | 스트림 A 30일/220 | ✗ | `collection.json` 미연결 |
| B | 스트림 B 180일/6×16 | ✗ | 수집기에 다중 스트림 없음 |
| B | 스트림 합성·dedup·출처 기록 | ✗ | `streamSource` 생성 경로 없음 |
| C | `queryMeshExclusions` 6개 적용 | ✗ | 스코어러가 config를 읽지 않음 |
| C | arm별 주제 파라미터 주입 | ✗ | 가중치가 모듈 상수 |
| C | 제외 전·후 metaHits 계측 | ✗ | 결과 계약에 해당 필드 없음 |
| D | hard/soft/allow 분리 | ✗ | 현행은 hard exclude와 allow만 지원 |
| D | soft penalty·단계적 복원 | ✗ | 후보 부족 시 전체 배제 해제만 존재 |
| D | 배제 전 후보와 오탐률 출력 | ✗ | 실험 JSON에 기록되지 않음 |

최종 판정은 다음과 같다.

- A: 모든 변경이 재생 하네스에서 실행됨 — **✓**
- B: 일부가 아니라 핵심 수집 변경 자체가 실행되지 않음 — **✗**
- C: 선언된 배제 파라미터가 실행 코드에 연결되지 않음 — **✗**
- D: 단계적 배제 정책과 계측이 없음 — **✗**

따라서 현재 상태에서 A/B/C/D 결과를 실행했다고 주장하면 안 된다. 우선 하네스에 `EXP_ARM`, 고정 입력 스냅샷, arm별 수집·주제·배제 설정 주입, 축별 텔레메트리를 추가해야 네 안을 공정하게 비교할 수 있다.
