## 2. 이 PR 이 하는 것 — 풀링

### ① 관심주제 축 (`src/utils/guidelineTopics.js`, 신설)
`config/guideline-topics.json`(질병명 188개, 11그룹)을 **PubMed 쿼리로 만든다.**

```
(<그룹 주제어>[Title] OR <그룹 주제어>[MeSH Terms])
  AND (지침 형식 축: PT 또는 제목의 guideline/consensus statement/…)
  NOT (veterinary·dental·dermatolog·cosmetic·acupuncture …)
```

- **그룹마다 쿼리 하나** — 이유 둘. ⓐ 188개를 두 축으로 한 줄에 이으면 10KB 를 넘어
  esearch GET 이 깨진다(그룹 단위 최대 2.7KB). ⓑ **어느 주제가 마르는지 보인다** —
  총계만 남기면 "심정지는 넉넉한데 중독은 반년째 0" 이 안 보인다. manifest 에 그룹별로 남긴다.
- **넓은 단어는 안 들어간다**(PeterJ 확정 08-15). `cardiac`·`trauma`·`airway`·`transfusion`·
  `triage`·`resuscitation`·`emergency medicine` … 대신 `cardiac arrest`·`major trauma`·
  `massive transfusion` 같은 질병·술기명이 덮는다. 테스트가 재도입을 막는다.
- 접두 stub 은 `antibiotic steward*` 처럼 **`*` 를 따옴표 밖**에 둔다 — 안에 넣으면
  PubMed 가 별표를 글자로 읽어 0건이 된다. 설정도 그에 맞춰 고쳤다.

### ② 2년 캐치업 (`monthly:24`)
`parseBackfillWindows` 가 `monthly:N` 을 받는다 → 30일짜리 창 N개(오래된 쪽부터).

한 창(`730-0`)으로 안 캐는 이유: esearch 는 `retmax` 로 자른다. 2년치를 한 번에
요청하면 **최신 N건만 오고 나머지는 조용히 사라진다** — 캐치업이라면서 최신만 또
긁는 꼴이다. 조각내면 각 조각이 `retmax`(백필 100) 안에 들어오고, 넘친 조각은
`truncated` 로 드러난다. 조각 사이에 구멍이 없는 것도 테스트가 못 박는다.

### ③ Add-on
데일리는 그대로 **최근 30일**을 본다. `mergeCandidates` 가 이미 published·rejected·큐를
대조하므로 신규만 얹힌다 — 구조가 이미 add-on 이다. 여기에 주제축을 같이 걸어
**백로그와 유입이 같은 모집단**이 되게 했다(다른 그물로 캐면 "예고에 있던 종류가
다음 날부터 안 나온다").

### ④ 레이트리밋
스펙이 2개 → 13개가 되었다. PubMed 는 키 없이 초당 3회다.
- 수집기: 동시 요청 **2개**로 제한(`Promise.all` 로 13개를 몰아치던 것을 교체).
- 백필 CLI: 최소 간격(키 있으면 110ms, 없으면 350ms) + 429·5xx 지수 백오프.
  census 가 실제로 429 로 통째로 죽은 적이 있다(HANDOFF 08-16 함정 ③).

### ⑤ 부수적으로 바로잡은 것
- 초집합 검증이 `results[0]`·`results[1]` 이라는 **인덱스**로 PT 쿼리를 찾고 있었다.
  스펙 앞에 무엇 하나만 끼면 엉뚱한 쿼리를 PT 로 착각한다 → id 로 찾는다.
- "두 쿼리가 다 죽으면 throw" 판정을 **핵심 두 축에만** 건다. 주제축 11개가 살아
  있는 한 현행 경로가 다 죽은 날도 "일부 성공" 으로 조용히 넘어가기 때문이다.
- `manifest.queries` 에 주제축 term(하나 1.5~2.7KB)을 안 넣는다 — 매일 상태 파일에
  20KB 씩 같은 문자열이 쌓인다. 성패·건수는 `manifest.topics` 에 남는다.
