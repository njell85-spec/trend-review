이게 어떻게 돌아가나

처음 보는 사람용 1분 요약 — 세부는 아래 PHASE 1~4 에 있다.

매일 새벽(한국 시각 06:30) GitHub Actions(깃허브가 정해진 시각에 코드를 대신 돌려 주는 장치)가 자동으로 돈다. PubMed(의학 논문 검색 사이트)를 뒤져 읽을 것을 고르고 → Claude Opus(AI)가 분석하고 → 웹페이지에 카드로 올리고 → 텔레그램으로 알린다. 사람이 할 일은 읽는 것과, 마음에 안 드는 것을 🗑 로 빼는 것뿐이다.

세 갈래(트랙)로 나뉜다 — 성격이 달라, 고르는 법도 분석하는 법도 다르다.

① 논문

갓 나온 임상 연구 → index.html

어떻게 고르나 — 최근 180일 PubMed 에서 관심 주제·저명 저널로 후보를 모아 점수를 매기고, 상위 후보를 Opus 가 다시 읽어 "침상에서 쓸모 있는가" 로 재정렬한다 → 하루 1편.

어떻게 분석하나 — PICO(임상 질문을 환자 P·중재 I·비교 C·결과 O 로 쪼개 읽는 틀): 임상 질문 / P·I·C·O / 핵심 결과 / 비평적 평가 / 임상 결론 · Practice Change. 수치는 초록·본문·레지스트리·확인된 권위 웹페이지에 적힌 값만 쓴다(추론 금지).

② 가이드라인

학회 진료지침 → guidelines.html

어떻게 고르나 — PubMed 출판유형(PT) 쿼리 + 제목 쿼리 + 질병명 188개 주제축으로 2년치를 미리 모아 둔다 → 발표 기관이 미국·유럽·한국인 것만 → 소아 전용은 규칙으로 제외 → 4가지 축(형식·발행처·규범성·공식성) 중 2개 이상 → 점수 → LLM(AI)이 "이 독자에게 값이 있나" 를 10점 만점으로 판정, 6점 이상만 발행 대기.

어떻게 분석하나 — 실무 요약 + 이전 판과의 차이: 무엇이 바뀌었는지(이전 권고 → 새 권고)를 축으로 잡는다.

③ 리뷰

주요 저널 종설 → reviews.html

어떻게 고르나 — 주요 저널(NEJM·JAMA·Lancet·BMJ·ICM·CCM)의 종설(한 주제를 통째로 정리해 주는 긴 리뷰 논문)을 모아 둔다 → 리뷰 전용 LLM 판정으로 순위를 매긴다. 가이드라인 기준을 그대로 쓰면 전부 탈락한다 — 리뷰는 정의상 "지침이 아니다".

어떻게 분석하나 — 요약이 아니라 번역: 원문의 절 순서를 그대로 따라 옮긴다. 원문을 못 구하면 웹에서 찾고, 그래도 못 구하면 "초록 범위만 옮겼다" 고 카드에 정직하게 적는다.

화면에는 리스트가 셋 있다.

예정리스트 — 페이지 맨 위. 앞으로 나갈 것들. ▶ 지금 발행 · 🗑 빼기 · 트랙 켜기/끄기.
발행리스트 — 페이지 본문. 분석해서 올린 카드들. 오늘 것은 펼쳐져 있고 지난 것은 접혀 있다.
누적리스트 — 페이지 아래. 지금까지 나간 것 전부의 표. 읽음 체크 · 🗑 삭제 · 🎬 자료화.
조금 더 — 왜 미리 모아 두나 · 뺀 것은 · 버튼은 어떻게 반영되나

미리 모아 두는 이유 — 매일 새로 찾으면 그날 좋은 게 없을 때 빈손이다. 2년치를 미리 모아 쌓아 두고(현재 가이드라인 672건 · 리뷰 397건 · 논문 12건) 거기서 매일 꺼내 쓴다. 새로 나온 것은 얹기만 한다. 그래서 "오늘 나올 게 없다" 가 없다.

뺀 것은 다시 안 온다 — 🗑 로 빼면 다시 뽑히지 않게 기록에 남는다. 실수로 뺀 것은 ▶ 로 되살린다.

버튼이 폰에서 바로 먹는 이유 — 사람이 손대는 자리는 브라우저에서 바로 GitHub 을 고친다. 버튼이 GitHub Actions 를 호출하거나 상태 파일을 직접 수정해서, 폰에서 눌러도 즉시 반영된다.
